RNSReticulum guide

Reticulum on WPAmesh

A handful of members are testing Reticulum over LoRa and the internet. These are the settings we use locally, plus the apps worth trying.

Before you start

For a full walkthrough of installing and configuring Reticulum, see kabi’s mesh guide. Its US RNode settings match ours, except we run TX power at 22 dBm.

Expect rough edges

Reticulum is experimental here. Ask in the Discord before buying hardware for it.

Pick a client

Sideband

Android · Linux · macOS · Windows

The most full-featured option: voice messages, real-time calls, file attachments, telemetry sharing and plugins. Good for power users, but battery life is pretty poor.

unsigned.io →

MeshChatX

Linux · macOS · Windows

A feature-rich, actively developed fork of MeshChat. Voice calls, multiple identities, phonebook, contact sharing, page archiving, maps and a polished modern UI.

git.quad4.io →

MeshChat

Linux · macOS · Windows

The original web-based client. Clean interface, a built-in NomadNet page browser, image, file and voice support, and an optional local propagation node.

GitHub →

Columba

Android

A native Android client in the latest Material Design. Early but actively maintained, and compatible with all other clients. Comes in a Python version (more stable, uses the official library) and a native Kotlin version (more power-efficient, smaller download).

GitHub →

Pyxis

T-Deck Plus

A self-contained node for the T-Deck, from the developer of Columba. Clean interface, a tad slow at times. WiFi and LoRa work well, BLE is very buggy, and audio calls work but at low quality.

GitHub →

Nomad Network

Linux · macOS · Windows (terminal)

The original terminal client. Encrypted messaging, file sharing and a built-in page server. The reference implementation for NomadNet pages.

GitHub →

WPAmesh backbone

Our test backbone connects Reticulum nodes over the internet. Add this to the [interfaces] section of your Reticulum config (usually ~/.reticulum/config):

Reticulum config
[[WPAMesh]]
  type = BackboneInterface
  enabled = true
  mode = boundary
  remote = mqtt.wpamesh.net
  target_port = 4242

It uses boundary mode because it’s an internet link. See interface modes for why.

RNode radio settings

These match the standard settings Chicagoland Mesh uses. They’re roughly as fast as Meshtastic’s Medium Fast, about 3 kbps.

Reticulum config
[[RNode LoRa Interface]]
  type = RNodeInterface
  enabled = yes
  port = /dev/ttyUSB0
  frequency = 914875000
  bandwidth = 125000
  txpower = 22
  spreadingfactor = 8
  codingrate = 5

914.875 MHz
Bandwidth
125 kHz
Spreading factor
8
Coding rate
4/5

22 dBm or your radio’s max

Change port to wherever your RNode shows up, for example /dev/ttyACM0 on Linux or a COM port on Windows.

Radios only hear each other when frequency, bandwidth, spreading factor and coding rate all match exactly. Don’t change them unless you’re joining a test.

Check your hardware’s TX power ceiling

Radios with an SX1262 or SX1268 go up to 22 dBm. Older SX1276 and SX1278 boards top out at 20 dBm. Set txpower to the highest value your radio actually supports, up to 22.

Hardware details and antenna advice are in the mesh guide’s Choosing a radio and Antennas and power pages.

Testing: longer range with SF10

Some of us are testing spreadingfactor = 10 for longer range. It trades speed for reach: about 1 kbps instead of about 3 kbps. A radio on SF10 can’t talk to one on SF8, so only switch if you’re part of the test, and ask in the Discord first.
