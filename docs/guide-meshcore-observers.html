MCMeshCore guide

Running an observer

Observers are nodes that feed what they hear to one or more MQTT servers for mapping and analytics. Ours shows up on CoreScope.

What an observer does

Not a bridge

Unlike Meshtastic MQTT, an observer does not create a bridge between two nodes over the internet. It only reports what it hears.

Some routes never show up on the map simply because nobody nearby is observing them. More observers mean a more complete picture of the mesh.

Standalone WiFi observer

If your node is ESP32-based, like the Heltec V4, it can connect directly over WiFi. Flash it with the observer firmware flasher.

These commands set it up to upload to Let’s Mesh (mqtt1), MeshMapper (mqtt2) and the WPAmesh CoreScope (mqtt3). Replace the WiFi name and password with your own.

Observer CLI
  1. set wifi.ssid YourWiFiNetwork
  2. set wifi.pwd YourWiFiPassword
  3. set mqtt.iata PIT
  4. set mqtt.rx on
  5. set mqtt.tx on
  6. set mqtt1.preset analyzer-us
  7. set mqtt2.preset meshmapper
  8. set mqtt3.preset custom
  9. set mqtt3.server mqtt.wpamesh.net
  10. set mqtt3.port 1883
  11. set mqtt3.audience mqtt.wpamesh.net
  12. reboot

After it reboots, run get mqtt.status to check that it connected.

Older instructions used slot 2

A previous version of these commands put the WPAmesh server in MQTT slot 2. It’s now slot 3, the first empty slot on the default firmware setup.

Node on an always-on computer

If your node can stay plugged into a computer that runs 24/7, one of these programs can feed its data to the server:

Node typeProgram
Companionmeshcore-packet-capture
Repeater or room servermeshcoretomqtt (needs custom firmware)

Broker settings for WPAmesh:

config.toml
[[broker]]
name = "wpamesh"
server = "mqtt.wpamesh.net"
port = 1883
transport = "tcp"

[broker.tls]
enabled = false

[broker.auth]
method = "token"
audience = "mqtt.wpamesh.net"

Firmware with packet logging

A repeater or room server attached to a computer needs firmware built with packet logging turned on. The standard flasher can’t enable it. It has to be set at build time.

Build it online

No local dev environment needed.

  1. Open Weebl’s online firmware builder
  2. Under Advanced Options, check Packet Logging. Debugging is optional, but lets your node report extra stats.
  3. When the build finishes, open the official flasher
  4. Scroll all the way to the bottom and choose Custom Firmware
