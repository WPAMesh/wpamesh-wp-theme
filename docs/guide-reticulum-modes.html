RNSReticulum guide

Interface modes

Each Reticulum interface can run in a mode that changes how it handles announces and paths. This is a reference for people running transport nodes.

Do you need this?

Only for transport nodes

Interface modes only matter if you’re running a Transport Node. If you aren’t, leave everything at the default and skip this page.

Quick reference

InterfaceMode
Client-facing interface on a hub or gatewaygateway
Internet uplink on a node with LoRa/RFboundary
Wide-area RF with transient usersaccess_point
External radio on a mobile or vehicle noderoaming
Everything elsefull (default)

The modes

full default

Full participation in discovery, meshing and transport. Use it when your node lives on a single medium and you don’t need anything special.

gateway gw

Everything full does, plus the node proactively resolves unknown paths on behalf of connected clients. Use it on the client-facing interface of a hub or gateway node: the interface your users connect to, not the uplink.

gateway and full handle announce propagation the same way. The only real difference is the proactive path lookup.

access_point ap

The interface stays quiet and won’t broadcast announces automatically, and paths expire faster. Path requests are still handled like gateway. Best for wide-area RF interfaces where users pop on briefly and then disappear.

roaming

For interfaces that are physically mobile from the wider network’s point of view. Use it on the external radio of a mobile node like a vehicle or phone. Paths expire faster to account for movement.

boundary

Marks an interface that bridges to a significantly different network segment. The classic example is a node with both a LoRa mesh and an internet uplink: set the internet-facing interface to boundary. Reticulum then manages announce flow so the fast internet side doesn’t flood the slow RF side.

Not a firewall

boundary doesn’t block traffic. It’s a flow management hint.
