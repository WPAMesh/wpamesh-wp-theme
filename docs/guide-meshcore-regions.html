MCMeshCore guide

MeshCore regions

Regions scope traffic to an area. WPAmesh uses the common US hierarchy, with an extra layer for Western PA between the state and the airport codes.

The hierarchy

  • *Global / unscoped
    • us
      • us-pa
        • wpaWestern PA
          • pitPittsburgh / Southwest PA
          • eriErie / Northwest PA

PIT and ERI are the IATA airport codes for Pittsburgh and Erie.

Why repeaters need the whole chain

A repeater only repeats a scoped message if it has a region with that exact name. The tree doesn’t help: a repeater with only pit won’t repeat a message scoped to wpa, and a repeater with no regions at all won’t repeat any scoped message.

So every repeater should carry the full chain, from us down to its airport code. Unscoped messages still go through either way, which is why a missing region is easy to miss until people start using scopes.

Setting up a repeater? Do this first

One repeater without regions can cut a scoped path in half. Set them before the repeater goes up, while you still have it on your desk.

Companions hear everything regardless of region. The app only picks the scope when you send.

Pit or eri?

The pit region only extends up to around New Castle and Grove City. Anything further north than that is eri.

Near a state line?

Repeaters along state or region borders, or ones that serve as a major hop for another area, may need to carry that area’s hierarchy too, for example us-oh or us-wv. Agree on it with both meshes rather than adding it by default. Check #friends-n-family for the neighboring mesh’s region config. Ohio Valley Mesh runs MeshCore, so they’re the likeliest to coordinate with.

Setting it up

For the Pittsburgh hierarchy:

CLI
  1. region def us us-pa wpa pit
  2. region save

Or, for an even bigger hierarchy that covers the whole East Coast:

CLI
  1. region def us us-east northeast us-midatlantic us-pa wpa pit
  2. region save

North of New Castle and Grove City, swap pit for eri. The reply to region def shows the resulting tree, so check it before saving. Every region it creates allows flood traffic by default.

Already have regions set?

region def doesn’t clear the existing tree. Names that already exist get moved under the new parent, and anything else stays. To start clean, region remove the regions you don’t want first.

Firmware older than 1.16?

region def needs firmware 1.16.0 or newer. On older firmware, add each region with region put <name> <parent>, starting from us. Before 1.15, region put also leaves the region blocked until you run region allowf <name>.

Unscoped traffic

Repeaters allow unscoped (*) floods by default. If you’ve ever run region denyf *, turn it back on before region save:

Repeater CLI
  1. region allowf *

Don’t go narrower than airport codes

Don’t add regions more specific than IATA codes. Many of us have to make very circular hops just to reach people the next city over, and a tighter region would cut those paths off.

Instead, make a channel just for your area and scope it to the nearest IATA code.

Region names are lowercase letters, numbers and hyphens. For how regions work in general, see the mesh guide’s Regions page.
